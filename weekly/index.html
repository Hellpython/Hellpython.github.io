Weekly Dev Log

한 주의 일을
다음 주의 자산으로.

무엇을 했는지만 나열하지 않고, 문제를 어떻게 이해했고 왜 그렇게 해결했는지, 실제로 무엇을 검증했는지 매주 짧게 남깁니다.

템플릿 준비됨 · 첫 기록은 실제 한 주의 내용으로 작성합니다.

10분 기록 순서

일요일에 아래 세 단계만 채워도 다음 작업을 시작할 맥락이 남습니다.

01 · CAPTURE

한 일을 적기

완료한 기능, 공부한 주제, 읽은 자료를 구체적인 결과와 함께 적습니다.

02 · EXPLAIN

판단을 설명하기

문제의 원인, 선택한 방법, 제외한 대안을 짧게 설명합니다.

03 · VERIFY

근거와 다음 일 남기기

실행한 검증과 남은 위험을 기록하고 다음 주 첫 행동을 정합니다.

주간 기록 템플릿

복사한 뒤 사실에 맞지 않는 항목은 지우고, 필요한 만큼만 작성합니다.

weekly-log.md

작성 원칙

나중의 내가 읽고 바로 작업을 이어갈 수 있는 정도면 충분합니다.

  1. 결과보다 판단을 남깁니다. 무엇을 왜 선택했는지가 다시 쓸 수 있는 기록입니다.
  2. 검증을 구체적으로 적습니다. “잘 됨” 대신 확인한 화면, test, command와 결과를 남깁니다.
  3. 모르는 것은 모른다고 적습니다. 미검증 항목과 남은 위험도 기록의 일부입니다.
  4. 10분 안에 끝냅니다. 빈칸을 억지로 채우지 않고 다음 주에도 계속 쓰는 것을 우선합니다.

공개 전에는 password, API key, 개인정보, 내부 URL과 로그가 포함되지 않았는지 확인합니다.
