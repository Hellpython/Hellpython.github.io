What I owned

Backend와 Database를 책임졌습니다

보고서와 8주간의 Tech Note에 반복해서 남은 담당 범위를 기준으로 정리했습니다.

01 / API CONTRACT

입력 규약과 수신 API

DumpingEvent와 DepartureEvent의 Pydantic model을 정의하고, FastAPI endpoint와 Swagger 문서로 팀 간 payload 규약을 맞췄습니다.

02 / PERSISTENCE

Append-only 저장 구조

UPDATE·DELETE를 제한하고 정정은 새 row와 invalidated_by 관계로 남기는 구조를 설계했습니다. 프로젝트 범위에서 차단 동작을 직접 확인했습니다.

03 / DATA PIPELINE

이미지·시간·위치 정제

base64 이미지는 파일로 분리하고 DB에는 경로를 저장했습니다. timestamp를 표준화하고 PostGIS로 위치 조회 기반을 만들었습니다.

04 / REAL TIME

실시간 전달과 연결 관리

WebSocket heartbeat를 비동기 task로 분리하고, 중복 전송과 끊김 문제를 줄인 뒤 센서→DB→화면 E2E 흐름을 점검했습니다.

Engineering decisions

구현보다 오래 남은 판단

문제가 생겼을 때 단순히 우회하지 않고, 데이터의 의미와 실패 방식을 먼저 정했습니다.

CORRECTION ≠ MUTATION

기존 증거를 고치는 대신 정정 이벤트를 추가

append-only 정책과 운영상 정정 요구를 함께 만족시키기 위해 원본을 유지하고 새 기록이 이전 기록을 무효화하도록 연결했습니다.

STORE REFERENCES

무거운 이미지와 검색할 metadata를 분리

base64 문자열을 파일로 디코딩하고 DB에는 접근 경로를 남겨, 관계형 DB가 이벤트 조회와 무결성에 집중하도록 했습니다.

COORDINATE SEMANTICS

센서 평면 좌표와 지리 좌표의 의미를 구분

LiDAR 좌표를 실제 위·경도로 단정하지 않고 프로젝트 좌표계로 저장했습니다. 지도 변환은 별도 시각화 metadata의 책임으로 분리했습니다.

VERIFY THE WHOLE PATH

개별 API 성공보다 E2E 흐름을 검증

image_data와 image_base64 불일치처럼 경계에서 생기는 결함을 찾기 위해 수신, INSERT, broadcast, 화면 표시를 한 흐름으로 반복 확인했습니다.
