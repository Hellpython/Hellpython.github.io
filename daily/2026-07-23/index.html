JavaScript 세미나

javascript-study의 19장과 20장 실습을 진행했습니다.

19 · PROTOTYPE

기능은 공유하고 상태는 분리한다

instance별 상태는 각 객체가 가지며 method는 prototype을 통해 공유합니다. property는 복사되는 것이 아니라 prototype chain을 따라 검색됩니다.

20 · STRICT MODE

실수하기 쉬운 동작을 error로 바꾼다

암묵적 전역, 일반 함수의 this, arguments 연결 등 sloppy mode와의 차이를 확인했습니다. class와 ES Module에는 strict mode가 자동 적용됩니다.

  • 용어 구분: prototype, [[Prototype]], __proto__, constructor는 서로 같은 말이 아닙니다.
  • property 확인: inherited property와 own property를 구분하고, shadowing과 삭제 후 검색 변화를 살펴봤습니다.
  • 도구의 역할: strict mode는 ESLint, TypeScript, test를 대신하지 않습니다. 각 도구는 다른 단계의 문제를 확인합니다.
  • 보안 연결: prototype pollution은 공유 prototype의 변경이 property 검색과 권한 판단에 영향을 줄 수 있는 사례입니다.

남은 질문: callback의 receiver를 다룰 때 bind·arrow function·class field 중 무엇을 선택할지, Object.create(null)과 Map의 실제 선택 기준, 경계를 넘는 값의 type을 어떻게 검사할지 더 확인합니다.
