일간 기록 템플릿

빈칸을 모두 채우기보다 오늘의 작업을 이어가는 데 필요한 항목만 작성합니다.

daily-log.md

작성 원칙

Daily는 자세한 보고서가 아니라 내일의 작업 재개를 위한 메모입니다.

  1. 한 일을 결과로 적습니다. “개발함”보다 무엇이 달라졌는지 남깁니다.
  2. 막힌 점을 숨기지 않습니다. 실패한 시도와 현재 가설도 다음 판단의 근거입니다.
  3. 검증을 구분합니다. 확인한 사실과 아직 예상인 내용을 섞지 않습니다.
  4. 내일 첫 행동은 하나만 정합니다. 다시 시작하는 비용을 줄이는 것이 목적입니다.

공개 전에는 password, API key, 개인정보, 내부 URL과 로그가 포함되지 않았는지 확인합니다.
